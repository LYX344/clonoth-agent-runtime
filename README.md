# Clonoth Agent Runtime

一个面向长期运行场景的多节点 AI Agent 运行时。核心由三层组成：Supervisor 负责进程、会话、任务路由与审批；Engine 负责节点执行、上下文构建、模型调用与工具调用；Adapter 负责把 Discord / QQ 等平台消息转换成统一的会话请求。

本项目基于 [HCPTangHY/Clonoth](https://github.com/HCPTangHY/Clonoth)（GPL-3.0）二次开发，在节点编排、输出质量门禁、上下文压缩、记忆注入与运维审批几个方向上做了大量改造。上游原版是一套通用的 Agent 框架，本仓库记录的是改造后的运行时设计与关键实现思路。

## 为什么做这些改造

单模型单会话的 Agent 在演示阶段够用，进入长期运行就会撞上四类问题：

1. **上下文膨胀**。一个会话跑几十轮之后，历史消息会挤爆窗口，简单的截断会丢掉关键事实。
2. **输出不可控**。模型会写出口头禅、八股词、格式错乱、超长消息，靠提示词约束并不可靠。
3. **角色越界**。不同任务需要不同的模型和不同的人设，单个 system prompt 会把所有能力揉成一团。
4. **线上不可运维**。进程挂了没人知道，危险命令没人拦，出了问题翻不到事件记录。

这套改造针对的就是这四件事。

## 核心设计

### 多节点编排

节点是一份 YAML，声明 id、模型、system prompt、可用工具、下游节点和输出处理器。Engine 按节点配置构造上下文并执行，任务可以在节点之间委派、切换、并发分发。

节点分两类：`ai` 类型走模型推理，`script` 类型在本地跑一段 Python，用于确定性处理。两类节点可以串在同一条链上。

### 输出质量门禁

模型输出不直接送到用户，而是先穿过一个 `script` 节点。这个脚本做几件事：

- 扫描禁用词表与八股词表
- 检测乱码、系统错误回显、固定句式
- 检测超长消息并按语义边界重新分段
- 不通过时返回 `reject`，把问题清单和原文回传给生成节点，要求定向重写

这样把「风格约束」从提示词里挪到了代码里，模型无法靠改写措辞绕过。

### 上下文与记忆

- 会话历史落在 `ConversationStore`，按 session 分文件
- 达到 token 阈值时触发压缩，保留最近若干轮，早期内容替换成结构化摘要
- 任务完成后异步生成轮摘要，用于替换旧任务的历史片段
- 记忆按 namespace 分册，支持关键词触发与常驻注入，按预算优先级裁剪

### 工具与技能

- 工具通过注册表暴露，支持本地 Python 工具与 MCP 远程工具
- 技能是一份带 frontmatter 的 Markdown，按关键词或常驻策略注入上下文
- 技能有优先级与 token 预算，超出预算时按优先级丢弃

### 运维与安全

- 危险命令走审批流，超时后工具收到明确错误而不是静默挂起
- 所有任务产生事件记录，可按 task_id 回放
- 计划任务支持 message 与 script 两种类型，script 以标准输出 JSON 作为注入内容
- 受保护路径与敏感命令在策略层拦截

## 目录

```
engine/       节点执行核心：推理步骤、上下文、记忆、工具、Hook、内置节点
supervisor/   进程管理、任务路由、会话、审批、调度、事件日志、管理 API
providers/    模型 Provider 实现与注册表
adapters/     平台接入层
tools/        本地工具实现
toolbox/      工具注册与运行时
skills/       技能注入单元
config/       节点定义与运行时参数
docs/         设计文档
examples/     脱敏示例配置
```

## 快速开始

```bash
pip install -r requirements.txt
cp .env.example .env          # 填入模型 API key
cp config.example.yaml config/runtime.yaml
python -m supervisor.main
```

节点定义示例见 `examples/node.example.yaml`，质量门禁示例见 `examples/qa_node.example.py`。

## 技术栈
