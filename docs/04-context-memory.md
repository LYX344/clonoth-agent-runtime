# 上下文与记忆

## 会话存储

历史消息按 session 追加写到 JSONL 文件，一行一条。相比全量重写，追加的写入成本低，崩溃时最多丢最后一行。

读取时按需加载最近 N 条，更早的部分走摘要。这种结构让「会话很长」不再等于「上下文很大」。

## 压缩

触发条件是 prompt token 数超过阈值，默认 256000。优先用模型返回的真实 token 数，拿不到时按字符估算。

压缩保留最近若干轮，默认 6 轮，更早的内容交给压缩节点生成结构化摘要。摘要要保留四类信息：用户身份与偏好、已确认的事实、未完成的任务、明确的否定结论。

压缩后如果还超，会再压一轮。压缩本身也是一次模型调用，所以阈值不能设得太低，否则会频繁触发，反而更慢。

## 轮摘要

单个任务完成后，异步生成一段任务摘要，用它替换掉旧任务在历史里的完整过程。触发门槛是工具调用次数达到 3 次，太简单的任务不值得摘要。

摘要带拒绝检测：如果摘要里出现拒绝话术或政策声明，直接丢弃，不写回历史。否则一段失败的摘要会污染后续所有对话。

## 记忆册

记忆按 book 分组，每条有 id、内容、关键词、优先级、扫描深度、是否常驻。

注入规则：

1. 常驻条目无条件注入
2. 关键词条目在最近 N 轮对话里匹配到才注入，N 由 `scan_depth` 决定，0 表示只看当前消息
3. 超出 token 预算时，按 priority 从高到低保留，低的丢弃

关键词支持正则，写法是 `/pattern/flags`。这条能力让匹配不必依赖字面词。

## 记忆的写入

两个入口：一是模型显式调用保存工具，二是任务结束后由提取节点扫描对话，挑出值得长期保留的事实。

提取节点要克制。什么都记等于什么都没记，记忆库膨胀之后，注入的噪音会盖过有用信息。所以提取规则偏向「用户偏好、项目事实、外部资源指针、明确的纠正」，不记过程性内容。

## 技能与记忆的区别

技能是「怎么做」，记忆是「关于谁、关于什么」。技能按任务类型注入，记忆按对话内容注入。两者共用预算，但分开存储，便于分别清理。
