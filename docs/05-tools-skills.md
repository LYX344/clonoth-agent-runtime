# 工具与技能

## 工具注册

工具是普通 Python 函数，声明名称、描述、入参 schema，注册进表之后就能被模型调用。执行时由运行时注入上下文对象，提供工作区路径、策略检查、审批入口和事件写入。

工具返回统一结构：状态、内容、可选附件。内容过长时自动转 artifact，只在对话里留引用，避免把大段文本塞进上下文。

## 本地工具与远程工具

本地工具直接在进程内执行。远程工具走 MCP 协议，支持 stdio、SSE、streamable HTTP 三种传输。MCP 客户端的配置文件放在数据目录，增删改之后重载即可生效，不用重启。

两类工具在调用方看来没有区别，注册表里统一成同一种描述。

## 审批

危险操作在策略层拦截。策略是一组正则，命中后生成审批请求，阻塞等待人工确认，默认超时 120 秒。

超时后工具收到明确错误，任务继续往下走，而不是无限挂起。这个设计是为了防止一个卡住的审批拖死整个会话。

审批记录进事件流，谁批的、什么时候批的、批的是什么命令，都能查。

## 工具追踪

每次工具调用生成一条 trace，包含入参、耗时、状态、输出摘要。输出超过阈值时落 artifact，对话里只保留引用。

这样做的原因是上下文预算。一次读取几万行的文件，如果全文进上下文，后面的推理就没空间了。

## 技能

技能是一份 Markdown，带 frontmatter：

```yaml
---
name: code-review
description: 代码审查流程
keywords: [review, 审查, diff]
strategy: normal
priority: 50
scan_depth: 6
---
正文...
```

字段含义：

| 字段 | 作用 |
| --- | --- |
| `keywords` | 触发词，支持正则 |
| `strategy` | `constant` 常驻注入，`normal` 按关键词触发 |
| `priority` | 预算不足时的保留顺序 |
| `scan_depth` | 往前扫描几轮对话，0 表示只看当前消息 |
| `order` | 同一批注入时的排序，值大的更靠近对话末尾 |

## 注入与裁剪

每轮先收集命中的技能与记忆，按 order 排序，再按 priority 从高到低塞进预算。超预算时丢低优先级的，不截断单个技能的内容。

这个策略的效果是：核心规范永远在，边缘知识按需出现。比把几十份文档全塞进 system prompt 更省，也更不容易让模型抓错重点。

## 技能与代码的边界

能用代码确定性解决的，不要写成技能。技能本质是提示词，提示词只能提高概率。像格式校验、长度控制、敏感词过滤这类，都该放在脚本节点里。
