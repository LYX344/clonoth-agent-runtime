# 运维

## 健康检查

Supervisor 暴露管理 API，`/health` 返回进程状态、worker 数、队列长度。外部监控定时打这个端点即可。

进程管理用简单的父进程模型：Supervisor 拉起 Engine 与 Adapter，记录 pid，异常退出后按退避重启。重启前写一条 checkpoint，恢复时从 checkpoint 读回任务状态。

## 计划任务

支持两种类型：

**message**：按 cron 注入一段文本，当作新的用户消息处理。适合定时提醒、日报。

**script**：按 cron 执行一条 shell 命令，解析标准输出的 JSON，把 `text` 字段作为注入内容。标准输出为空时按配置决定是静默跳过还是只注入前缀。

cron 用五段式，UTC 时区。任务配置存在 YAML 里，改完立即生效。

## 事件与排障

事件流是排障入口。常见判断路径：

- 任务卡住：看最后一条事件停在哪个阶段
- 工具失败：看 trace 里的错误和入参
- 审批超时：看审批事件的创建时间和结果
- 上下文异常：看压缩事件前后的 token 数

事件按天切分，超过保留期的自动清理。

## 数据清理

数据目录会随时间膨胀：会话文件、事件日志、artifact、备份。清理任务按配置的保留天数删除过期文件，备份单独保留更长时间。

清理前先统计体积，超过阈值才执行，避免空跑。

## 部署

单机部署用 systemd 或 supervisor 托管主进程。多机部署时，Supervisor 与 Engine 可以拆开，通过 remote worker 协议通信。

配置与数据分离：配置进版本库，凭据进环境变量，数据进持久卷。这样换机器只需要搬数据卷和填环境变量。
