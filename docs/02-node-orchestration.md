# 节点编排

## 节点是什么

节点是一份 YAML 描述的执行单元，包含身份、模型、提示词、工具权限、下游关系和输出处理器。Engine 读到节点后，按配置构造上下文，调用模型，执行工具，最后把结果交给 output 指定的处理器。

一个最小节点长这样：

```yaml
id: assistant
type: ai
name: 通用助手
description: 处理日常问答
model: gpt-4o-mini
output: quality_gate
tool_access:
  mode: all
```

## 字段说明

| 字段 | 作用 |
| --- | --- |
| `id` | 节点唯一标识，委派与切换都用它寻址 |
| `type` | `ai` 走模型推理，`script` 在本地执行 Python |
| `model` | 模型标识，由 Provider 层解析 |
| `prompt` | system 消息列表，支持模板变量 |
| `tool_access.mode` | `all` 开放全部工具，`none` 关闭工具 |
| `tool_mode` | `native` 使用原生函数调用协议 |
| `skills` | 技能注入策略，`mode: all` 或按关键词触发 |
| `delegate_targets` | 允许委派的下游节点白名单 |
| `output` | 输出处理器节点 id，`__source__` 表示原样返回 |
| `persistent` | 是否常驻，常驻节点保留自己的上下文链 |
| `memories` | 记忆册绑定，`none` 表示不读写记忆 |

## 三类任务关系

**委派**。父节点把一个子任务交给下游节点，下游在独立 session 里跑完，结果回到父节点。适合边界清晰、可并行的活。上下文有三种继承方式：

- `fresh`：完全空白的上下文，每次都是新开始
- `fork`：复制父节点当前对话历史
- `accumulate`：首次空白，之后续用子节点自己的上下文链

`context_key` 用来把多个任务绑到同一条上下文链上，不同 key 互不污染。

**切换**。当前节点把对话交给另一个节点，自己立即结束，用户的下一条消息由新节点处理。适合角色切换，比如从闲聊切到教学。目标节点能看到此前的对话历史。

**并发分发**。同一轮里对多个节点同时发起委派，各自独立执行，结果全部回收后再由父节点汇总。

## Session 隔离

子任务跑在独立的 child session 里，跟父会话的 history 分开存储。默认 24 小时不活跃后过期，单个父会话最多关联 50 个子会话。这样做的原因很直接：子任务的中间过程不该污染主对话的历史窗口。

主会话本身也走 `ConversationStore`，历史按 session 分文件追加，压缩时直接操作存储层，不再依赖快照机制。配置里留了灰度开关，出问题可以回退到旧的 snapshot 方案。

## 动态创建节点

节点是配置，不是代码。运行时可以按模板生成新节点：读取模板 YAML，替换 id、名称、描述、记忆册，写入节点目录，并把它追加到调用者的下游白名单里。新节点立刻可用，不需要重启进程。

这条能力让「给某个长期任务开一个专属助手」变成一次配置操作，而不是一次发版。

## 失败处理

- 模型调用失败按指数退避重试，默认三次，退避上限 30 秒
- 子任务超时可以取消，取消后父节点收到明确状态
- 工具异常写进事件流，不吞掉
- 节点执行有步数上限，防止在工具循环里出不来
